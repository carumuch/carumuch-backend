# Code Review Guide

## 목적

이 문서는 `carumuch-backend`에서 코드 리뷰를 수행할 때 확인해야 할 기준을 정의합니다.

리뷰는 칭찬이나 요약보다 결함, 회귀 위험, 테스트 누락을 먼저 찾는 데 집중합니다.

---

## 리뷰 우선순위

다음 항목을 우선 확인합니다.

1. 동작 오류 가능성
2. 기존 기능 회귀 위험
3. 계층 책임 위반
4. 데이터 무결성 및 트랜잭션 경계 문제
5. 인증/인가 누락
6. 테스트 또는 검증 누락

---

## 핵심 체크포인트

`docs/code-style.md` 위반이 없는지 먼저 확인하고, 그중에서도 회귀 가능성이 큰 항목을 우선 봅니다.

### 구조와 책임

- controller가 repository를 직접 호출하지 않는가
- business logic이 controller나 infrastructure에 새어 나오지 않았는가
- 레거시 패턴을 신규 코드에 그대로 확장하지 않았는가

### 도메인 모델

- public setter를 추가하지 않았는가
- 엔티티가 단순 데이터 컨테이너처럼만 사용되지 않는가

### 검증과 안정성

- 변경에 맞는 테스트 또는 검증이 있는가
- `./scripts/verify.sh` 기준으로 설명 가능한 상태인가
- 예외 처리, 권한 검증, 이벤트 발행 순서에 누락이 없는가

---

## 리뷰 응답 방식

리뷰 결과는 아래 원칙으로 정리합니다.

1. 문제를 먼저 적습니다.
2. 심각도 높은 순서로 정리합니다.
3. 가능하면 파일 경로와 라인 근거를 함께 적습니다.
4. 영향과 이유를 함께 설명합니다.
5. 요약은 필요할 때만 짧게 덧붙입니다.

찾은 문제가 없으면 그 사실을 먼저 명시하고, 남아 있는 테스트 공백이나 확인이 필요한 위험을 함께 적습니다.
